## How?

<details>
<summary>TL;DR, character codes are generated by compressing JSON through zstd and base64-encoding it.</summary>

The way character codes are generated is by taking the original JSON and
compressing it through [zstd](https://github.com/facebook/zstd) and then
base64-encoding it. This is very easy to reverse, and can be used to create
custom movesets externally without the need for Roblox or JJS.

Decoding a code with base64 and zstd gives the original JSON. From there, a
script can modify the JSON to create a custom moveset.
</details>

## Usage

First, install the library using `npm install @dnd-ed/jsshenanigans`.

Then, in a JavaScript file, import the library as `jss` and create a character:

```js
import * as jss from "@dnd-ed/jsshenanigans";

const character = new jss.Character();
```

From here, you can create skills using `character.create.skill()`.

```js
character.create.skill("Super Cool Skill", { cooldown: 5 });
```

Nodes live in their own module, so import them too:

```js
import * as nodes from "@dnd-ed/jsshenanigans/nodes";

character.create.skill("Punch", [nodes.HITBOX({ damage: 5 })]);
```

Check out `demo/demo.js` for a full example.

## Features

- [x] Support for every documented node, condition and property, including
  `PARTICLE`, `LOOK` and `SETMELEE`
- [x] Support for all skill types
- [x] Exports as a JJS-valid character code
  - I recommend you paste it into JJS to check if it's working, then copy the character block's export
- [x] Branch support
- [x] Variable names for animations, easing styles/directions, effects, etc
- [ ] Custom nodes
  - [ ] Domain node
- [ ] Fake rigs
  - [ ] Fake rig animations

## Requirements

Node.js **22.15+** (it ships `zstd` in `node:zlib`). No required runtime
dependencies.

## zstd backends

The codec picks a backend automatically:

1. `node:zlib` --- the default, native, and the only one that can compress.
2. [`fzstd`](https://www.npmjs.com/package/fzstd) --- an optional, pure-JS
   fallback. It can only *decompress*, so it is used for reading codes when
   `node:zlib` is unavailable.

Set `JSSHENANIGANS_ZSTD_BACKEND` (e.g. to `"fzstd"`) to prefer a specific one.
Run `npm run bench` to compare the installed backends; `node:zlib` is several
times faster, which is why it stays the default.
